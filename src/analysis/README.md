# src/analysis — AI 분석·보고서 담당 (1/2: 분석)

## 담당 테이블
- `report_sections` — 보고서 섹션별 초안(분류, 요약, 신뢰도 근거)
- 참고(읽기 전용): `document_versions`

## 참고 자료
- `docs/architecture/myWiki_v2_supabase.sql`
- 대시보드/리포트 화면 시안(`mywiki-wireframe.html`) — 신뢰도 표시 방식(높음 0.75↑ / 보통 0.50~0.74 / 낮음 0.50↓ / 보류) 그대로 따른다.

## 이 파트가 해야 하는 일
1. `document_versions`의 정제된 Markdown을 읽어 6개 분류(제품·기술/경쟁사/고객·수요산업/공급망·생산/정책·규제/시장·경영) 중 하나로 분류한다.
2. 핵심 내용을 요약하고, 신뢰도 점수(0~1)를 계산한다 — 계산 근거(출처 수, 공시 여부, 매체 간 일치 여부)를 함께 남긴다.
3. **근거가 2건 미만이거나 매체 간 서술이 크게 갈리면 섹션을 만들지 않는다.** 이건 프로젝트 전체의
   "근거 없으면 답을 만들지 않는다" 원칙이 리포트 생성 단계에도 그대로 적용되는 부분이다 —
   여기서 느슨해지면 Agent 쪽에서 아무리 엄격해도 소용없다.

   **예외: DART 공시(`sources.source_type='disclosure'`)는 이 다건 근거 요건 중
   신뢰도(교차검증) 기준에서만 면제된다.** 공시는 금융감독원 전자공시시스템(DART)이
   내는 1차 공식 기록이라, 뉴스처럼 여러 매체가 같은 사실을 다르게 서술할 위험이 없다
   — 문서 자체가 이미 원본이므로 다른 출처와 교차검증할 필요가 없다. 그래서 공시
   문서는 **1건만 있어도(그리고 다른 후보와 주제가 달라도) `reliability_score` 기준을
   통과한 것으로 본다.**

   단, **`importance_score`(중요도)는 공시라도 면제하지 않는다.** 신뢰도는 "이 근거를
   믿을 수 있는가"이고 중요도는 "이 내용이 사업적으로 중요한가"라 서로 다른 축이다
   — 공시라고 자동으로 중요해지지 않는다(실측 예시: 임원이 회사 주식 3,620주(지분율
   0.00%)를 장내매수했다는 공시는 `importance_score=2`로 나왔다 — 단일 출처 여부와
   무관하게 그냥 사업적으로 무의미한 내용이라 낮은 것). importance까지 면제하면
   사소한 행정 공시가 전부 위키 후보가 되어버리므로, 중요도·랭킹 기준은 공시에도
   뉴스/RSS와 똑같이 적용한다. 뉴스/RSS 등 나머지 출처 타입은 신뢰도 기준도
   그대로(근거 2건 이상, 매체 간 서술 일치) 따른다.

   구현 위치: `src/report/selector.py`의 `_is_eligible_candidate`가 `candidate.source_type
   == 'disclosure'`면 `reliability_score` 기준만 건너뛴다. `importance_score`·
   `min_ranking_score`(설정 시)·용량 제한(`max_candidates`/`category_limits`)은 공시도
   뉴스/RSS와 동일하게 적용받는다 — 면제 대상은 "교차검증이 안 된다"는 판단 기준뿐이다.
4. 근거로 쓴 `document_version_id`를 명확히 기록해서, `report` 담당이 `report_citations`를 채울 수 있게 한다.
